# Security Policy

## Supported versions

Security fixes are provided for the latest release on the `main` branch.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Earlier releases | No |
| Unreleased development builds | No |

## Reporting a vulnerability

Do not report security vulnerabilities through public issues, discussions, or pull
requests.

Use GitHub's private vulnerability reporting for this repository. Open the
**Security** tab, select **Advisories**, and choose **Report a vulnerability**. Include:

- the affected version and Android version;
- a clear description of the vulnerability and its impact;
- reproducible steps or a minimal proof of concept;
- any prerequisites needed to reproduce the issue; and
- suggested mitigations, if known.

Do not include personal data, production credentials, or data obtained from systems
you do not own or have permission to test.

## Response process

Reports will be acknowledged within five working days. After validation, maintainers
will coordinate remediation and disclosure through the private advisory. Release
timing depends on severity, exploitability, and the availability of upstream fixes.

Please allow a reasonable remediation period before public disclosure. Maintainers
will credit reporters in the advisory unless anonymity is requested.

## Testing guidelines

Only test installations, devices, accounts, and networks that you own or are
explicitly authorized to assess. Avoid privacy violations, service disruption,
denial-of-service testing, social engineering, and accessing or modifying other
people's data.
